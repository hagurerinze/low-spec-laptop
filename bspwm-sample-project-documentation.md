# BSPWM Sample Configuration Project

## Project Overview

-   **Project duration:** 2 days
-   **Main goal:** Create and test a separate sample configuration for
    BSPWM.
-   **System:** Debian with BSPWM
-   **Main tools:** GitHub Copilot, Claude, BSPWM, SXHKD, tint2, feh,
    and nm-applet

This project was a practical exercise in learning basic Linux desktop
configuration. I used AI tools for some guidance, but I also changed and
tested the configuration myself instead of only copying and pasting
generated files.

The project started with a small experiment and later became a BSPWM
configuration project.

## 1. How the Project Started

I had recently started trying GitHub Copilot. I was exploring its random
features when it showed a command that could generate a web-style HTML
todo list.

I was curious, so I ran the command and tested the result. I added one
todo item and planned to check it again the next day.

When I returned, the todo list was missing. I do not know whether this
happened because I moved the file or for another reason.

I tried to investigate the problem using the Firefox Developer Tools
(F12). I also checked Brave, but I could not find the cause. There is
still some uncertainty about which browser was checked and what was
tested. At least one browser was checked, but I could not confirm the
full history from memory.

The investigation was stopped because there was not enough reliable
information to continue.

## 2. Starting the BSPWM Project

After that, I asked GitHub Copilot to generate a sample BSPWM
configuration.

The generated sample included these files:

-   `bspwmrc`
-   `sxhkdrc`
-   `tint2rc`

At first, I did not know how to create a custom BSPWM session without
replacing or overwriting the original BSPWM configuration.

I asked Claude for help with this part. After getting the initial
guidance, I continued the work by myself.

The sample files were stored separately in:

``` text
~/.config/bspwm-sample/
```

This allowed me to test a separate configuration instead of directly
replacing the main configuration.

## 3. Problems During Testing

### 3.1 Dunst

Dunst showed an error during the first tests.

One possible cause was switching between XFCE and BSPWM. There may have
been duplicate processes or startup tasks, but this was only a guess.

After a reboot, Dunst worked normally again. The exact cause was not
diagnosed.

### 3.2 Desktop Switching Shortcut

After I could enter the custom session, I found a problem with this
shortcut:

``` text
super + shift + n
```

The shortcut was intended to move a window to desktop `n`, where `n`
represents the desktop number.

I tried restarting BSPWM with:

``` bash
bspc wm -r
```

This did not fix the problem. Rebooting also did not fix it immediately.

After several tests and another attempt to use the custom configuration,
the shortcut started working again.

I do not know the exact cause. One possibility is that an old process
was still running and the configuration became normal after it was
stopped with `pkill`, followed by starting the default process again.
This explanation has not been confirmed.

### 3.3 nm-applet Did Not Appear

The next problem was `nm-applet`.

It did not appear in the tint2 panel, even though the panel
configuration included the system tray item.

The relevant tint2 panel item setting was:

``` ini
panel_items = LTSC
```

The problem appeared to be related to the `bspwmrc` file generated by
GitHub Copilot.

I changed parts of the BSPWM configuration with help from Claude.
Instead of guessing the file location, Claude directly executed the file
that needed to be checked.

After changing the configuration, `nm-applet` started correctly.

## 4. Final Result

The custom BSPWM session now boots with my own edited configuration.

This project took about two days. It was also a small practical exercise
in basic Linux desktop administration.

I used AI tools to get information and help with troubleshooting, but I
did not use them only to generate files for copying. I checked the
configuration, changed paths and settings, tested the results, and
learned from the problems.

Some problems were solved, while others remain without a confirmed
technical explanation. Those uncertain points are marked as
possibilities, not facts.

### 5.1 `bspwmrc` --- My Edited Version

This is the version currently used by my custom session.

``` sh
#!/bin/sh
bspc monitor -d 1 2 3 4

bspc config border_width 2
bspc config window_gap 6
bspc config split_ratio 0.50
bspc config borderless_monocle true
bspc config gapless_monocle true

bspc rule -a Gimp state=floating

sxhkd -c ~/.config/bspwm-sample/sxhkdrc &
tint2 -c ~/.config/bspwm-sample/tint2rc &
feh --bg-fill /home/hagure/Pictures/"Pastel Fox-Eared Girl with Milk Tea.png" &
nm-applet &
```

Main points:

-   It starts four desktops.
-   It uses a 2-pixel window border and a 6-pixel window gap.
-   It starts SXHKD and tint2 using files inside the sample directory.
-   It sets the wallpaper with `feh`.
-   It starts `nm-applet`.

### 5.2 `bspwmrc1` --- Claude Template Version

This is the template version provided with Claude's help.

``` sh
#!/bin/sh
pgrep -x sxhkd > /dev/null || sxhkd -c "$HOME/.config/bspwm-sample/sxhkdrc" &
tint2 -c "$HOME/.config/bspwm-sample/tint2rc" &

bspc monitor -d 1 2 3 4

bspc config border_width 2
bspc config window_gap 6
bspc config split_ratio 0.50
bspc config borderless_monocle true
bspc config gapless_monocle true

bspc rule -a Gimp state=floating

sxhkd &
tint2 &
feh --bg-fill /home/hagure/Pictures/"Pastel Fox-Eared Girl with Milk Tea.png" &
```

This template contains startup commands near the beginning and also
starts SXHKD and tint2 again later. This may cause duplicate startup
processes. The exact effect depends on which commands are running.

The template also starts `sxhkd` and `tint2` without the same explicit
configuration paths in the later commands.

### 5.3 `sxhkdrc` --- Keyboard Shortcuts

This file was not changed from the sample version. The path in my
`bspwmrc` was set to use this file directly.

``` sh
# Terminal
super + Return
    x-terminal-emulator

# Focus windows
super + {h,j,k,l}
    bspc node -f {west,south,north,east}

# Move windows
super + shift + {h,j,k,l}
    bspc node -s {west,south,north,east}

# Switch desktops
super + 1
    bspc desktop -f '^1'
super + 2
    bspc desktop -f '^2'
super + 3
    bspc desktop -f '^3'
super + 4
    bspc desktop -f '^4'

# Send focused window to a desktop
super + shift + 1
    bspc node -d '^1'
super + shift + 2
    bspc node -d '^2'
super + shift + 3
    bspc node -d '^3'
super + shift + 4
    bspc node -d '^4'

# Window controls
super + space
    bspc node -t \~floating
super + f
    bspc node -t \~fullscreen
super + q
    bspc node -c

# Reload bspwm and sxhkd
super + shift + r
    bspc wm -r
```

## 6. Notes and Limitations

-   The missing todo list was not fully diagnosed.
-   The Dunst error disappeared after reboot, but its cause was not
    confirmed.
-   The desktop shortcut problem stopped appearing after repeated tests,
    but the exact cause is unknown.
-   The `nm-applet` issue was traced to the BSPWM startup configuration,
    based on the tests made during this project.
-   The configuration comparison records the files used during testing.
    It does not prove that every difference caused a specific problem.

## 7. Final Reflection

This project was not only about making BSPWM start with a custom panel.

It gave me a chance to practice:

-   Reading Linux configuration files.
-   Understanding how BSPWM starts other programs.
-   Using separate configuration paths.
-   Testing keyboard shortcuts.
-   Checking panel and system tray settings.
-   Troubleshooting startup problems.
-   Using AI tools as a source of information instead of relying only on
    generated commands.

The final configuration is not a complete desktop environment. It is a
small personal BSPWM setup and a learning project.
